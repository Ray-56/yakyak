版本：v1.0；规划日期：2026-10-16；对象：Ray-56/yakyak。所有目标初始为未开始；当前状态只以 progress.json 为准。

范围确认：用户于 2026-10-18（Asia/Shanghai）在本会话明确确认本版本的功能范围、排除项及自研/复用边界。记录见 [AC-00-01 部分验收报告](../acceptance/ch00/AC-00-01.md)；本次确认不代表整个 AC 或第 00 章验收通过。

## 终极目标

由用户本人用 Rust 实现一个可编程通信引擎，以 RustPBX 公开仓库中经过本路线图核定的非 AI 功能类别为参考，覆盖 SIP/B2BUA、实时媒体、基础 PBX 应用、外部编程接口、浏览器接入、必要管理与运维。先正确完成通信基础，再向外扩展。

这里是**功能能力对齐**，不是复制源码、目录、所有私有 API、UI 外观或性能宣传数字。也不是承诺完整实现通信行业的一切协议。所有协议支持范围都以公开的兼容矩阵与测试证据为准。

参考依据为 2026-10-16 查阅到的公开 main 页面/文档/部分源码，初始化现场已取得并验证 RustPBX commit `0b1414bb3460a42abce8596f8f07d9b6d2889975` 的可读对象及四个文件，详情见 [reference-lock.json](../references/reference-lock.json)。路线图中的功能清单冻结于本版本，不自动追逐上游 main 的新增功能。未编译或实际测试 RustPBX；初始化检查不证明 YakYak 通信功能。

## 明确排除

AI Agent、LLM、ASR、TTS、实时/离线转写、通话总结、知识库、模型工具调用、AI 质检与模型服务协议适配全部排除。普通录音、双向 PCM、DTMF、固定提示音、音频电平检测不属于 AI，保留。

RustPBX 文档说明商业扩展位于独立仓库，因此商业计费结算、语音批发平台、完整商业联络中心、商业可视化流程设计器、CRM/WFM 等不算本公开仓库对齐目标。[R02]

T.38 传真、SS7/模拟硬件、移动推送电话、完整聊天产品、视频转码/完整 SFU、进行中通话无损跨机迁移，不在本轮已核定范围。参考源码的注释、占位、实验模块或后来新增功能，不能自动成为需求；若核对固定 commit 后发现遗漏的真实非 AI 核心能力，应进入范围变更记录，明确补章，不悄悄忽略。

## 哪些自己写，哪些可以复用

SIP 消息/事务/Dialog/B2BUA、SDP 协商、RTP/RTCP 会话管理、呼叫状态机、媒体路由/生命周期、PBX 应用与管理业务由本人编写。rsipstack、rustrtc 作为阅读与对照对象，不直接替代本次希望学习的整个内核。

允许使用运行时、网络 I/O、HTTP/WebSocket 基础库、序列化、日志、数据库、成熟 TLS/DTLS/SRTP 密码实现、成熟 Opus 编码器和重采样组件。WebRTC 的连接与媒体编排由 YakYak 负责，但浏览器内核和 TURN 服务端不自行重做。每个重要依赖通过 ADR 记录“复用什么、仍然自研什么、如何独立验收”。“亲自写核心”不等于重新实现密码学。

优先一个仓库、一个服务端进程、一个 crate 内按职责分模块。稳定后才抽出独立 crate；更晚才根据测量拆进程。前端不是早期目标，UI 技术不要求 Rust。早期一个固定用户配置文件和内存状态足够；数据库不是首次打通电话的前提。

## 六个架构约束

1. Transaction、Dialog、Call Session、Call Leg、Media Session 使用清晰标识与职责，不用一个 Call-ID 表包办全部。
2. 协议状态机输出动作，运行时执行 I/O；有可替换时钟和可重放输入。
3. 一通会话有明确协调者，一路最终媒体输出有唯一所有者；避免多个功能任务并发乱写同一个发送端。
4. 信令成功、媒体成功、业务成功分别表示；命令接受不是操作完成。
5. 所有队列、超时、重试、抓包、录音和外部请求均有上限；后台与数据库不得阻塞媒体热路径。
6. 关闭分为停止业务、停止媒体、等待协议状态按定时器收尾；没有流量时任务仍能退出。
