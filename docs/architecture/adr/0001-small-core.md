# ADR-0001：单 Cargo 包起步，逐步长出内核

状态：Accepted（2026-10-21，用户在本会话明确确认）。关联：INIT-07、AC-00-04。

## 决定

初始化只有 std-only CLI 壳与测试。先保持一个 Cargo 包（package），后续解析、事务、运行时、媒体按实际章节在包内增加模块，不预建多包 workspace 和 27 套空模块。

当前包只有 `src/main.rs`，对应一个 binary crate。以后按实际需要在同一包内增加 `src/lib.rs`，可形成 library 和 binary 两个 crate；这不等于拆成多个 Cargo 包。

模块职责、接口和测试边界稳定后，若出现真实复用、独立维护或发布、依赖隔离等需求，再评估抽成独立 Cargo 包及其 crate。

## 原因

用户要亲自理解通信行为。过早设计大目录、依赖和服务，容易掩盖尚未成立的通话主链路。

## 替代与后果

一次建立完整分层 workspace 看似规整，但前期接口大多只是猜测。包内仍需明确模块职责，避免循环职责和全局共享状态。后续按上述实际需求重审，并非永远禁止拆分。

## 用户确认记录

2026-10-21（Asia/Shanghai），用户在收到单包起步、模块内分工、实际拆分条件，以及 package 与 crate 的区别说明后回复“同意01 和03”。据此接受本 ADR，并将原“单 crate 起步”表述明确为“单 Cargo 包起步”。本次记录设计选择，不代表通信内核已实现，也不启动后续 AC。
